# How to build your master profile

Your master profile (`MASTER_PROFILE.md`) is the foundation — the better it is, the better every
tailored resume. It should hold **everything**, because tailoring can only *select* from what's here.

## The fastest path

1. Drop whatever you have into [`raw/`](raw/) — see [raw/README.md](raw/README.md) for ideas. Old
   resumes and a LinkedIn export alone are a great start.
2. In Claude Code, say: **"Build my master profile from the files in profile/raw."**
   Claude will read everything and fill in `MASTER_PROFILE.md`, asking you about anything unclear.
3. Read it over and correct anything. Add accomplishments the old resumes left out.

## What makes a profile strong

- **Capture more than one resume's worth.** List *every* role, project, tool, and win. A single
  resume shows ~30–40% of this; tailoring needs the other 60% to draw from for different jobs.
- **Quantify everything you can.** Numbers are what make bullets land and what screeners latch onto:
  percentages, dollars, time saved, users, scale, team size, revenue. "Improved performance" → "cut
  API p95 latency 42% (1.2s → 700ms), saving ~$18k/mo in compute."
- **Use strong, specific verbs.** Led, built, shipped, migrated, automated, negotiated, reduced,
  grew, designed. Avoid "responsible for" and "helped with."
- **List the exact tools and technologies** for each role — these are prime keyword matches. Include
  both the common name and any acronym (Kubernetes / K8s, Applicant Tracking System / ATS).
- **Keep it truthful.** Everything here should be defensible in an interview. If you're unsure a
  number is right, note it and fix it later.

## Keeping it fresh

Update the master profile whenever you finish a project or hit a milestone — it's much easier to
capture a win the week it happens than to reconstruct it a year later at 11pm before an application.
